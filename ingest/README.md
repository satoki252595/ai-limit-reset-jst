# Auto-ingest routine (every 2 hours)

0. Writes go through the GitHub connector, never `git push` (the box git has no GitHub auth). Read current files from GitHub (`get_file_contents` on `satoki252595/ai-limit-reset-jst@main`, or `git fetch && git reset --hard origin/main` for a read-only local copy), edit locally, run tests locally, then write with the connector:
   - one file: `create_or_update_file` (pass the current blob `sha`);
   - several files: `push_files` (max 4 `$file:` arguments per call, so split into several calls; put data/ingest files before tests if tests change).
   Never `git commit` locally for this repo; after pushing, re-sync with `git fetch && git reset --hard origin/main` so the local copy never drifts. If the local copy has unrelated uncommitted changes, discard them and re-sync before starting.
1. Search X newest-first since `state.json.newest_seen_id` for posts from accounts in `allowlist.json` (add `-from:grok -is:retweet`). Also read self-replies and quote posts by allowlisted accounts. For accounts with a `rule` field (e.g. `@bot`: top-level posts only), apply it.
   Search terms (OR-combined, case-insensitive), run as `(from:A OR from:B ...) (TERMS) -from:grok -is:retweet`:
   `reset OR resets OR reseted OR resetting OR "rate limits" OR "usage limits" OR "usage limit" OR "weekly limits" OR "5-hour" OR "banked reset" OR "reset bank" OR "reset available" OR "reset token" OR "reset card" OR "starts fresh" OR "hit refresh" OR "fresh usage" OR "brand new usage" OR "full reset" OR propagated OR "on the house" OR quotas OR "Day" (catches "Day N/ Reset")`
   Completion phrases to match against open `scheduled` entries: `propagated OR "all reset" OR "it is done" OR landed OR "in the bag" OR "is live"`.
   A second, author-free query catches leaders not yet allowlisted: `("reset usage" OR "reset rate limits" OR "reset everyone" OR "reset weekly limits" OR "banked reset" OR "reset card" OR "reset tokens" OR "reset quota" OR "reset quotas") (codex OR claude OR cursor OR grok OR gemini OR antigravity OR muse OR GLM OR "Coding Plan" OR ZCode OR bolt OR Forge OR kimi OR kiro OR copilot OR windsurf OR devin) -from:grok -is:retweet`; any non-allowlisted author found here goes to `pending.json` (and a proposed allowlist entry), never straight to the site.
1b. Non-X sources: WebFetch every entry in `sources.json` with `official: true` (help articles, status RSS, changelogs, blogs, GitHub release feeds, forum announcement RSS). Look for resets announced only there (e.g. help-center notes listing global/banked reset dates, model-launch blog posts carrying a banked reset, emails quoted on official pages). Official-page resets may be published with `url` set to an X post only if an allowlisted X post exists; otherwise add them to `pending.json` with the page URL (the site's URL schema is X-only).
   Entries with `official: false` (third-party trackers) are discovery only: use them to find candidates, then verify on the official source. Never publish from a tracker alone.
1c. Unannounced / observed resets (users notice limits refilled; Reddit/X user reports; tracker "observed" rows; email or in-app banner reports by users): publish ONLY when an allowlisted account or official page acknowledges it; otherwise add to `pending.json` with `channel` (e.g. `observed`, `email`, `in-app banner`, `livestream`) and a `reason`.
2. Open the full text (note_tweet). Publish only clear usage-limit resets by allowlisted authors.
3. Record the stated time verbatim in `source_time_text`; if a time is stated, set `source_tz` (IANA, e.g. `America/Los_Angeles`; "PST" written during US daylight time = PDT) and `source_local_datetime`, and derive `effective_jst_iso`.
4. Each new entry MUST include:
   - `summary` (Japanese, source of truth, short — never the full post text, no images)
   - `summary_i18n.en` (required) and other locales where reasonable (`zh-Hans`, `zh-Hant`, `ko`, `es`, `fr`, `de`, `pt-BR`, `hi`, `id`) — translations of the Japanese summary only, no new facts
   - `effective` (ja) and `effective_i18n.en`; `scope` / `scope_i18n.en`; if `note` is set, `note_i18n.en`
   - For `type: "scheduled"`: `time_precision` (required) — `exact` (a specific clock time, e.g. "10am PST"; needs `source_local_datetime`), `deadline` (an upper bound such as "by EOD", "by midnight"; the reset may come earlier, and `source_time_text` must keep the original wording), or `approximate` (no time / vague timing). Leave `time_precision: null` for `immediate` / `banked`.
   - `source_tz_assumed` (boolean, required whenever `source_tz` is set): `true` if the post does not state the zone and it was inferred (e.g. "by EOD" read as Pacific), `false` if the post states it.
4b. Confirmation: on every run, also look for completion posts (e.g. "reset done / propagated / landed") by allowlisted authors for entries still `status: "scheduled"`. When one exists, set `status: "done"`, `confirmed_url` (the post URL) and `confirmed_utc` (its timestamp, `YYYY-MM-DDTHH:MM:SSZ`, must match the post ID's snowflake time), and update `effective` / `effective_i18n.en`. This applies even before the scheduled/deadline time; the page then shows "Reset done at HH:MM" and stops the countdown.
5. Anything borderline (time zone missing, unclear scope, unverified author) goes to `pending.json` with a `reason` and is never published.
6. Keep the 30-day pruning, run `node tests/validate.mjs`, and push only if it passes. ALWAYS write `state.json` at the end of every run (even with no changes) via the GitHub connector (`create_or_update_file`), together with `data.json`/`pending.json` when they changed (`push_files`). Confirm the Pages workflow run for the new commit succeeds (`actions_list` → `list_workflow_runs`).
